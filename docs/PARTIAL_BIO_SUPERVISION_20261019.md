# R7/R8：部分标注 BIO 序列监督可行性（2026-10-19）

状态：已实现独立 GT 联系方式、姓名及任职年月的**局部可核实 O 类背景监督**，但尚不具备整份简历的完整 O 标注。本轮不训练、不部署模型，不修改正式解析、五维评分、DeepSeek 或 settings.json。

## 目标与工程判断

PaperPro 外部 20 PDF 固定挑战集仍为 **167/276（60.51%）**。此前文字行分类器和字符后缀提议器都未通过开发集门禁。继续在相同的 5 份开发 PDF 上调参数和筛选后缀，不能证明跨版式泛化。

本轮验证上游条件：独立 GT 只标注了少量职位、公司、学校字段，怎样正确生成部分观测序列？在缺少真实背景标签时，不得把所有剩余字符自动标为 O。

## 已实现的数据接口

- app/diagnosis/partial_bio.py：仅接受 PDF bytes、独立 GT 和经过检查的训练源 ID，复用唯一、非重叠的字符片段对齐接口，输出按原始字符索引编制的部分 BIO 序列。
- 对独立 GT 正例使用 B-WORK_ROLE/I-WORK_ROLE、B-EMPLOYER/I-EMPLOYER、B-SCHOOL/I-SCHOOL；同一原文行可有不同字段的两个正向片段。
- 未标注字符保留为 None，observed_mask 为 false（UNKNOWN）；仅将明确来自独立 GT 的 `basicInfo.personalEmail/phoneNumber/name`、`workExperience.N.employmentPeriod.startDate/endDate` 中**格式合规、原文唯一逐字对应、且不与任何已标注职位/公司/学校片段冲突**的字符标记 `O`。姓名须为独立词项；年月须为有效 YYYY.MM、YYYY-MM 或 YYYY/MM，拒绝年份缩写与“至今”。这里的 O 是“不是这三类目标字段”，并非“不是任何实体”。
- 任意背景值重复、缺失原文、无效格式、仅匹配更长词语/日期的局部字符串或与正向字段冲突时弃权；未标注文字不因邻近已标注字段而被扩展为 `O`。背景标注记录独立 GT 字段路径、来源类型及精确字符区间；统计会拒绝无来源的 O。文件 SHA-256、页码、坐标保留供溯源，同一 PDF 不得重复计为训练来源。
- 数据内容仅在内存处理。CLI 只输出安全聚合计数，不打印 PDF 原文、姓名、联系方式、GT 字符片段或标签原始序列。
- 来源限定 Apache-2.0 SyntheticResumeData 固定 commit 3ecd09129f65955e743aacf67f2785fcee10d461，训练池编号 21–35；开发集 36–40、新冻结测试集 41–60、原产品挑战集均未读取。

## 下一项最小里程碑

部分 BIO 序列目标已在 `docs/PARTIAL_BIO_OBJECTIVE_20261019.md` 中通过穷举对照。新增 189 个 O 字符后再次检验：全 O/全职位分别错 477/988 个已知字符，而两种只记住已标注位置、在 **8,694** 个未知字符上输出相反结果的策略仍得到近零损失。新增背景确实更能约束全实体的粗糙退化，但未解决 UNKNOWN 的**不可辨识性风险**。如需扩充 O，只能引入独立复核的真实非目标区间，不能靠缺失标注或相邻文字填充背景。

只有能够验证完整字段片段召回、拒识和误报，并且在开发数据上优于旧方法，才能考虑有限 CPU 模型实验与新的封存数据评价。现有产品的人工校对权限与外部基准 167/276 保持不变。
