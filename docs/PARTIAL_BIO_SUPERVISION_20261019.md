# R7/R8：部分标注 BIO 序列监督可行性（2026-10-19）

状态：已实现、独立 GT 训练源可复现；**尚不具备完整监督序列模型的合法 O 类背景标签**。本轮不训练、不部署模型，不修改正式解析、五维评分、DeepSeek 或 settings.json。

## 目标与工程判断

PaperPro 外部 20 PDF 固定挑战集仍为 **167/276（60.51%）**。此前文字行分类器和字符后缀提议器都未通过开发集门禁。继续在相同的 5 份开发 PDF 上调参数和筛选后缀，不能证明跨版式泛化。

本轮验证上游条件：独立 GT 只标注了少量职位、公司、学校字段，怎样正确生成部分观测序列？在缺少真实背景标签时，不得把所有剩余字符自动标为 O。

## 已实现的数据接口

- app/diagnosis/partial_bio.py：仅接受 PDF bytes、独立 GT 和经过检查的训练源 ID，复用唯一、非重叠的字符片段对齐接口，输出按原始字符索引编制的部分 BIO 序列。
- 对独立 GT 正例使用 B-WORK_ROLE/I-WORK_ROLE、B-EMPLOYER/I-EMPLOYER、B-SCHOOL/I-SCHOOL；同一原文行可有不同字段的两个正向片段。
- 未标注字符保留为 None，observed_mask 为 false（UNKNOWN）；虽然标签词表包括 O，但**本轮观察到的 O 背景标签计数恒为零**。
- 冲突、重复、无法定位的 GT 字段弃权；文件 SHA-256、页码、坐标保留供溯源。同一 PDF 不得作为两个独立训练来源。
- 数据内容仅在内存处理。CLI 只输出安全聚合计数，不打印 PDF 原文、姓名、联系方式、GT 字符片段或标签原始序列。
- 来源限定 Apache-2.0 SyntheticResumeData 固定 commit 3ecd09129f65955e743aacf67f2785fcee10d461，训练池编号 21–35；开发集 36–40、新冻结测试集 41–60、原产品挑战集均未读取。

## 已运行实验

执行：

    uv run --python 3.12 python -m scripts.benchmark_partial_bio

| 项目 | 实测 |
|---|---:|
| 训练来源 PDF | 15 |
| PDF 原生文字行 | 601 |
| 总字符数 | 9,706 |
| 已观测正例字段字符 | **477（4.9145%）** |
| 保留 UNKNOWN 的字符 | **9,229（95.0855%）** |
| 已观测字段片段 | 62：职位 24，公司 28，学校 10 |
| 真正标注为背景 O 的字符 | **0** |
| 伪造的背景负例 | **0** |
| 普通完整监督 BIO 模型的训练数据门槛 | **不满足** |

即使有 31 条源行恰好完全由一个已标注字段覆盖，也不表示获得了 O 类背景的负例。常规序列分类器在没有已知背景类别时，无法可靠学习实体与非实体的完整边界。部分标签条件似然虽然允许未知位置参与边际化计算，但仍需要防止退化解以及检验已确认背景标注。

新增反例测试覆盖同一行两个字段的 B/I、日期及剩余字符 UNKNOWN、重叠与重复 GT 弃权、训练/保留数据屏障、重复来源拒绝、聚合输出无私人文字及真实 CLI 执行。

    uv run --python 3.12 python -m pytest tests/test_partial_bio.py -q

## 下一项最小里程碑

优先建立**独立来源的明确背景标注接口**，例如对已标注且能唯一溯源的联系方式、确定日期或经过人工确认的非字段字符区间，标记已核实非目标内容。该操作必须严格限制来源与标注范围，不能因某一段文字没有出现在 GT 中就将整段标 O。

只有能够验证完整字段片段召回、拒识和误报，并且在开发数据上优于旧方法，才能考虑有限 CPU 模型实验与新的封存数据评价。现有产品的人工校对权限与外部基准 167/276 保持不变。
