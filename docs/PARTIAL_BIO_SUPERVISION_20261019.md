# R7/R8：部分标注 BIO 序列监督可行性（2026-10-19）

状态：已实现独立 GT 联系方式的**局部可信 O 类背景监督**，但尚不具备整份简历的完整 O 标注。本轮不训练、不部署模型，不修改正式解析、五维评分、DeepSeek 或 settings.json。

## 目标与工程判断

PaperPro 外部 20 PDF 固定挑战集仍为 **167/276（60.51%）**。此前文字行分类器和字符后缀提议器都未通过开发集门禁。继续在相同的 5 份开发 PDF 上调参数和筛选后缀，不能证明跨版式泛化。

本轮验证上游条件：独立 GT 只标注了少量职位、公司、学校字段，怎样正确生成部分观测序列？在缺少真实背景标签时，不得把所有剩余字符自动标为 O。

## 已实现的数据接口

- app/diagnosis/partial_bio.py：仅接受 PDF bytes、独立 GT 和经过检查的训练源 ID，复用唯一、非重叠的字符片段对齐接口，输出按原始字符索引编制的部分 BIO 序列。
- 对独立 GT 正例使用 B-WORK_ROLE/I-WORK_ROLE、B-EMPLOYER/I-EMPLOYER、B-SCHOOL/I-SCHOOL；同一原文行可有不同字段的两个正向片段。
- 未标注字符保留为 None，observed_mask 为 false（UNKNOWN）；仅将 `basicInfo.personalEmail` 和 `phoneNumber` 中格式合法、能在 PDF 原文中唯一**逐字匹配**、且不与任何已标注职位/公司/学校片段冲突的字符区间标记 `O`。这里的 O 是“不是这三类目标字段”，并不是“不是任何实体”。
- 重复出现的联系方式、缺失原文、无效格式和与正向字段冲突时弃权；且未标注文本不得因为邻近联系方式就被填充为 `O`。背景标注须保留 `independent_gt_contact` 来源及精确字符区间，汇总统计会逐一核对每个 `O` 字符具有对应来源。文件 SHA-256、页码、坐标保留供溯源。同一 PDF 不得作为两个独立训练来源。
- 数据内容仅在内存处理。CLI 只输出安全聚合计数，不打印 PDF 原文、姓名、联系方式、GT 字符片段或标签原始序列。
- 来源限定 Apache-2.0 SyntheticResumeData 固定 commit 3ecd09129f65955e743aacf67f2785fcee10d461，训练池编号 21–35；开发集 36–40、新冻结测试集 41–60、原产品挑战集均未读取。

旧版确实没有 O 类监督；本轮仅补充少量**明确非三类目标字段的联系方式背景**。这给模型提供了真实、来源可追溯的部分对照，但 **91.52%** 的字符仍为 UNKNOWN，尚不能用完整监督序列损失；局部 O 与实体之间的对照也不足以证明对任意背景的拒识能力。可用部分标签训练目标需要进一步证明其可辨识性及在新的未见样本上的误报控制。

新增反例测试覆盖同一行 B/I 与联系方式 O 并存、日期及剩余字符 UNKNOWN、重复邮箱和无效电话弃权、联系方式与公司字段重叠弃权、不能将邮件地址子串错误匹配为 O、汇总过程拒绝无证据 O、训练/保留屏障、重复来源拒绝、聚合输出不泄漏原文与 CLI 实测。

## 下一项最小里程碑

下一步应明确**部分标签序列学习的合法监督目标与可辨识性**，以已证明的正向片段、局部联系方式 O 为基础，构造只在 `observed_mask=True` 上计算的受约束目标，并验证一个全部预测为目标字段的退化解不会因少量 O 而被错误接受。如需扩充 O，只能引入独立复核的真实非目标区间，不能靠缺失标注或相邻文字填充背景。

只有能够验证完整字段片段召回、拒识和误报，并且在开发数据上优于旧方法，才能考虑有限 CPU 模型实验与新的封存数据评价。现有产品的人工校对权限与外部基准 167/276 保持不变。
