# PaperPro · V3.0 / V2.0 需求残差与准入（2026-10-28）

依据：用户提供的《简历增强智能体 DEMO 功能设计说明书 V3.0（2026-10-28）》与《简历增强智能体 DEMO 功能流程图 V2.0（2026-10-27）》。本记录只记录实际仓库证据；不把方案文档视为已经实现。

| 流程 | 当前证据与残差 | 下一步准入 |
| --- | --- | --- |
| F01 上传 | 已支持 PDF/Word/图片/粘贴与大小控制；现有 FastAPI 无任务 ID、账号权限、删除接口与持久原件。 | 接受状态存储与访问身份设计之后才能增加正式任务/版本/删除功能。 |
| F02 OCR/解析 | 本地 OCR、固定解析、超过 10 秒等待反馈和原文保留已存在；通用句/段/bbox 索引、可靠取消与重试事件尚不完整。 | 独立 OCR 质量和取消生命周期验收。 |
| F03 来源字段 | 结构化编辑、原文文本与部分 PDF 几何位置已存在；逐字段 original/current/value_origin、完整双向锚点及历史未实现。 | 先选定唯一来源字段归属和版本写入权威。 |
| F04 质量校正 | 基本字段可编辑、诊断输入变化会使当前结果失效；尚无持久修改历史/并发保存。 | 作为正式版本管理的一部分开发，而非添加第二个客户端真相源。 |
| F05 目标确认 | 目标 JD、五模块开关、后端默认权重已存在；V3 要求目标职位必填、可编辑能力项/权重尚未实现，当前系统允许仅公司。 | 新版门禁会改变既有可用流程，需与先完成、少阻断的产品目标协调。 |
| F06 五维诊断 | 五维与原文证据、评分、局部模块失败已有；本轮加入 complete/partial/unavailable 报告状态及无有效模块建议禁入；缺单模块重试、永久历史。 | 优先做真正受影响模块的局部重试，不同时新造缓存和 task runner。 |
| F07 建议生成 | 原有 9 项固定模板及可选核查；V3 要求真实样本不凑数、仅有效发现，尚需专项改造。 | 基于证据裁减，不能直接删除产品原有输出。 |
| F08 建议采纳 | 现有勾选仅选中导出，未实现非空实际修改→已采纳待办→独立完成和后端事件。 | 需要可验证版本/任务 owner 后再接持久状态，避免“打勾即完成”。 |
| F09/F10 清单与报告导出 | 已有选中项 TXT/PDF 与简历 DOCX/PDF；本轮新增完整诊断报告 TXT/PDF，保留关闭/失败状态和版本标识，空报告禁导出。 | 继续验收跨版本权限与导出历史（当前无服务器任务账本）。 |
| F10 历史 | 当前仅浏览器短时交接，无跨会话任务、恢复版本、保存冲突管理。 | 先确立隐私、身份、删除与并发所有权，不用仅靠 localStorage 冒充服务端版本。 |

## 本轮已落地的最小可验证增量

- `POST /api/diagnosis/report/export`：当前报告快照 TXT/PDF，包含生成时间、统计日期、规则版本、校对稿指纹、目标和五维状态/结论/证据。
- 导出范围：5 个模块中的已完成个数；关闭/失败不算完成，全部无效时拒绝导出；客户端与服务端均拒绝五个模块全关后启动新分析。
- 报告页直接下载，导出失败不丢当前诊断；导出期间修改输入时丢弃旧请求的下载结果。
- 旧 `/api/diagnosis/export` 选中优化/面试清单保留；原始简历、诊断评分和推荐稿算法不改。

## 明确产品决策冲突（没有擅自解决）

V3.0 F09 明确写“建议与局部示例，不整篇代写”，而此前用户明确要求“先给完整推荐稿，再可选核查”。仓库目前保留“用户主动采用的完整推荐稿”，不擅自删除既有功能；是否把完整稿改成纯建议模式需产品决策。

## 诚实验收边界

本轮没有账号/角色认证、任务持久化、源文档永久存储、事件日志或跨会话版本恢复。客户端提供的报告快照不是服务器鉴权过的历史文档。以上属于 F01/F03/F08/F10 的后续独立工程边界。
