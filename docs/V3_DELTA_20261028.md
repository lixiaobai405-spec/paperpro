| 流程 | 当前证据与残差 | 下一步准入 |
| --- | --- | --- |
| F01 上传 | 已支持 PDF/Word/图片/粘贴与大小控制；现有 FastAPI 无任务 ID、账号权限、删除接口与持久原件。 | 接受状态存储与访问身份设计之后才能增加正式任务/版本/删除功能。 |
| F02 OCR/解析 | 本地 OCR、固定解析、超过 10 秒等待反馈和原文保留已存在；通用句/段/bbox 索引、可靠取消与重试事件尚不完整。 | 独立 OCR 质量和取消生命周期验收。 |
| F03 来源字段 | 结构化编辑、原文文本与部分 PDF 几何位置已存在；逐字段 original/current/value_origin、完整双向锚点及历史未实现。 | 先选定唯一来源字段归属和版本写入权威。 |

| F07 建议生成 | 已将部分报告的固定建议限制为成功执行的来源模块；无对应疑点时不补造风险建议。全量报告仍保留原有 9 项模板，尚非逐项证据精确筛选。 | 后续独立验收真实样本的去重、建议触发和不凑数。 |

## 本轮已落地的最小可验证增量

- `POST /api/diagnosis/report/export`：当前报告快照 TXT/PDF，包含生成时间、统计日期、规则版本、校对稿指纹、目标和五维状态/结论/证据。`POST /report` 在可选 AI 解读完成后为整个报告签发 HMAC 完整性标记；仅原样服务端签发的报告能再次导出，篡改字段、互换两份报告以及缺少签名均拒绝。
- 导出范围：5 个模块中的已完成个数；关闭/失败不算完成，全部无效时拒绝导出；客户端与服务端均拒绝五个模块全关后启动新分析。
- 报告页直接下载，导出失败不丢当前诊断；导出期间修改输入时丢弃旧请求的下载结果。
- 部分报告的建议带 `source_module`，仅来自执行成功的模块。原文证据与疑点不再被隐式截到前 4/30 条；单条极长文字的截断会明确注明，嵌套格式无效返回 422。
- 旧 `/api/diagnosis/export` 选中优化/面试清单保留；原始简历、诊断评分和推荐稿算法不改。

## 明确产品决策冲突（没有擅自解决）

V3.0 F09 明确写“建议与局部示例，不整篇代写”，而此前用户明确要求“先给完整推荐稿，再可选核查”。仓库目前保留“用户主动采用的完整推荐稿”，不擅自删除既有功能；是否把完整稿改成纯建议模式需产品决策。

## 诚实验收边界

本轮没有账号/角色认证、任务持久化、源文档永久存储、事件日志或跨会话版本恢复。新签名只证明报告导出与**当前服务签发的 JSON 内容相同**，不代表用户身份、经历真实性或历史任务所有权；任何人仍可用自己的输入生成新报告。默认签名密钥仅保留在当前 Python 进程，服务重启后需要重新生成报告；多个工作进程需要配置相同的 `PAPERPRO_REPORT_SIGNING_KEY`（UTF-8 长度至少 32 字节）。旧 `/api/diagnosis/export` 清单接口仍接受客户端报告，本轮未宣称其具备同样的完整性签名。正式跨会话持久与权限需要独立设计，属于 F01/F03/F08/F10 的后续边界。
