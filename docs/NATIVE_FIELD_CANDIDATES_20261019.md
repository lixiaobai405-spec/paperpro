# PaperPro R7/R8：无 GT 的 PDF 职位/公司文字行候选实验

日期：2026-10-19。状态：**候选发现原型已通过工程测试，但在独立挑战集表现不达标，不部署**。

## 目标与方法

从原始 PDF bytes 出发，在**完全没有 GT JSON、公司、职位正确答案**的前提下，枚举包含潜在职位或机构名称的原生 PDF 文字行。研究的是 GT-blind candidate recall（候选行覆盖率），不是把文字行正确切分成职位字段，更不是 HR 评分。

- 候选实现：app/diagnosis/native_candidate_lines.py
- 离线双划分工具：scripts/benchmark_native_candidate_lines.py
- 测试：tests/test_native_candidate_lines.py 与 tests/test_native_candidate_benchmark.py
- 外部来源：Apache-2.0 SyntheticResumeData，commit 3ecd09129f65955e743aacf67f2785fcee10d461
- 开发池：编号 21–40，共 20 份；固定挑战集：1–10、101–105、201–205，共 20 份。
- 生成顺序：先读取 PDF 并生成候选，之后才加载独立 GT 用于评价；测试验证加载顺序与划分屏障。
- 候选只保留来源页码、归一化坐标、PDF 原文行及未经确认状态。不会生成公司/职位结构事实、学历、任期、工作经历或匹配分；不会使用收费 API、训练模型或修改现有产品。
- 正确答案缺漏：没有 GT 对应的候选行只能叫“未获当前标注支持”，**不能**直接定义为误报；也没有足够的真负例估计精确率。

| 测量 | 开发池 21–40 | 固定挑战集 |

| 职位候选行覆盖 GT | 34/45（75.56%） | **27/50（54.00%）** |
| 公司候选行覆盖 GT | 36/46（78.26%） | **29/49（59.18%）** |

注意：GT 标签如果只在 OCR 可识别、非原生文字行中出现，不纳入原生候选的可达上界；而候选行“包含一个词”还不是完整字段提取。表中任何比例都不是**用户真实简历解析准确率或预测录用概率**。

**开发池→挑战集退化明显，无法通过当前产品所需的可泛化解析门槛。** 不接入 app/diagnosis/api.py，不自动写入候选人的任职记录，也不覆盖现有人工确认的 review_hints 流程。不得因为固定挑战集的失败而再编辑词表并反复报告“未见集”成绩，否则污染评测。完整 PDF→结构化 Schema 仍以先前冻结的 **167/276（60.51%）** 为可信基线。

## 后续路径与实验纪律

下一项应采用**PDF 原生文字行、位置与上下文结构特征**，利用第三方独立 GT 提供的唯一可定位标签做受监督字段发现。一个可检验的候选方向是小型 CPU 文字行标记器：职位/机构/学校是明确的正向标签；没有对应标注的未知行不能直接当负例；重复锚点需要放弃或经人工核实。必须先在开发样本中设计/锁定配置和目标指标，再使用**一组新的、从未用于任何调参的合成 PDF**作真实独立评价。已有固定挑战集只用于历史对照，不能再次用于调整词表。

发布门槛不变：端到端解析有净提升、来源位置可追溯、原文件不变、不制造不存在的任职/日期、人工确认之前不参与匹配评分。未通过则保留原有人工校对流程。不要将本实验未见的行预测权重或未经校准的数字展示为招聘质量分数。

## 运行命令（完全无需上传真实简历）

    uv run --python 3.12 python -m scripts.benchmark_native_candidate_lines --split train_candidate_feasibility
    uv run --python 3.12 python -m scripts.benchmark_native_candidate_lines --split holdout_evaluation
