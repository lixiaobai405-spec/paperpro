# R7/R8 合成解析质量测试（2026-10-19）

## 使用方法

在 PaperPro 根目录运行：

    uv run --python 3.12 python -m scripts.benchmark_resume_parsing --include-ocr

只测 PDF 与 DOCX（不运行耗时 OCR）：

    uv run --python 3.12 python -m scripts.benchmark_resume_parsing

自动化测试：

    uv run --python 3.12 python -m pytest tests/test_synthetic_parsing_quality.py -q

输入全部在内存生成，不使用真实个人简历，不调用外部 API，不在磁盘生成简历。测试模块位于 app/diagnosis/synthetic_parse_bench.py、synthetic_ocr_bench.py、scripts/benchmark_resume_parsing.py；Chrome 场景位于 frontend/e2e/candidate.spec.js。

## 字段测量口径

对每份简历事先定义 13 个字段：姓名、邮箱、目标职位、个人简介、关键技能、工作公司、工作职位、工作开始年月、工作结束年月、工作职责中的案例标识、项目名称、学校名称、证书。

字段完全匹配率 = 匹配真值的字段数 / 总预期字段数。源文件 SHA-256 核对 bytes 保持不变。未纳入手机号、职位之外的履历区段与复杂证书类型，因此不能将该值当作所有真实简历的完整召回率。

## 文档结果（受控合成）

| 阶段 | 格式 | 样本 | 字段格 | 正确 | 比率 |
|---|---|---:|---:|---:|---:|
| 修复前 | 10 DOCX + 10 原生 PDF | 20 | 260 | 248 | 95.38% |
| 修复后 | 10 DOCX + 10 原生 PDF | 20 | 260 | 260 | 100% |

包含中文/英文、Word 段落与表格、年月日期的短横线/破折号/中文「至」、中文「年/月」等变体。

修复了中文「2022年01月—2025年06月」的结构化日期识别，以及原生 PDF 提取时某些字体映射造成的软连字符 U+00AD。请注意 100% 仅对这 20 份刻意构造的样本成立。

## 图像结果（受控合成）

| 阶段 | 格式 | 样本 | 字段格 | 正确 | 比率 |
|---|---|---:|---:|---:|---:|
| 修复前 | PNG/JPEG 中英混合 | 4 | 52 | 37 | 71.15% |
| 修复后 | PNG/JPEG 中英混合 | 4 | 52 | 49 | 94.23% |

实际运行本地 RapidOCR。图片是高分辨率合成截图，两张施加约 0.7° 轻微旋转。它们不代表真实手机拍照数据的总体分布。

OCR 原文暴露三项可修复的结构错误：
- 邮箱域名出现形如 example. invalid 的多余空格，已限定仅在邮箱形态的片段修正；
- 章节标题 Work Experience 有时被 OCR 合并为 WorkExperience，已按固定标题白名单匹配；
- 中文全角连接横线、竖线相近字符会干扰日期、公司/职位切分，已加白名单。

另有 3 个字段仍识别错误：两个工作句子中的成果编号字符，以及一个英文姓名的词间空格。它们是 OCR 文字本身的误差，不能靠猜测补写；用户可在第二步人工校对。

## 浏览器与设备边界

- 真实 Chrome 场景已验证：浏览器内生成合成扫描图，调用真实 FastAPI 上传与本地 OCR，进入可编辑表单，设目标后生成诊断。
- Pixel 7 与 iPhone 13 设备描述的 Chrome 模拟验证：PNG/JPEG 文件选择、上传表单、解析结果进入校对页、窄屏不产生横向溢出。
- 设备模拟不能证明真机相册或相机系统权限完整可用；需要 Android/iOS 真机验收。
- 20 份真实简历字段完整率及手机照片 OCR ≥85% 仍必须用获得许可的代表性真实样本评估，不能用本合成通过率替代。

**验收约束**：保留原件，记录失败项，不修改真实数据以满足测试阈值，不将模拟结果包装成 HR 生产效度。
