# PaperPro｜GT-blind PDF 字符片段提议器实验

日期：2026-10-19。状态：**实验已完成，开发门禁未通过，不部署、不读取冻结测试集。**

## 目标与数据边界

当前正式产品的外部固定 20 份 PDF→结构化 Schema 指标仍是 167/276（60.51%），这次实验没有修改该指标对应的产品实现。

候选来源：Apache-2.0 SyntheticResumeData，commit 3ecd09129f65955e743aacf67f2785fcee10d461。固定数据划分：

- 训练：21–35，15 份，独立 GT 中可保留的正向字符片段：职位 24，公司 28。
- 开发验证：36–40，5 份，在实验开始前已固定。
- 全新冻结测试：41–60，20 份，**本轮没有读取**。
- 原产品外部挑战集：1–10、101–105、201–205，20 份，绝不用于训练和调参。

## 实际实现

- app/diagnosis/span_proposer.py：对独立 GT 的职位/公司正向字符区间计算字段特有的字符串结尾、字符二/三元组和长度分布；没有把未标注文字、姓名、联系方式或不存在的字段当负例。依据训练正例的最低十分位固定候选接受阈值。
- 推理时只接收 PDF bytes 和临时训练参数，不接收任何 GT。候选从 PDF 原生文字行产生，使用标点、日期范围、空格以及训练所得字符串后缀提出字符区间 start_char/end_char。
- 每一项必须完全等于原文切片，含页码、归一化坐标、字段类别、排序值和 unverified 标记。排序值不是经过校准的置信度或任职概率，**不能直接采纳，更不能加入五维评分**。
- scripts/experiment_span_proposer.py：训练池原文和 GT 只在内存读取；开发 PDF 的候选必须先由 GT-blind 方法生成，之后才能加载独立标注。对照旧词表的同额度候选和完整候选清单。
- 模型参数不存磁盘，不使用 GPU、外部收费 API，不连接 app/diagnosis/api.py。所有输出为聚合数字，不打印原始履历、职位、公司或联系方式。

## 开发集实测（36–40；5 份，目标职位 13 项、公司 14 项）

| 指标 | 旧规则（整行包含 GT） | 新片段提议器（片段完整等于 GT） |
|---|---:|---:|
| 职位 | 10/13 | **4/13** |
| 公司 | 10/14 | **9/14** |
| 待人工核对候选项 | 33 | **18** |

这两个指标并不是同一测量对象：旧方案按整行包含 GT 计数，新方案要求**提取的字段片段完全匹配**。为避免混淆，也按同一口径分别统计：

| 开发集字段 | 旧原文行包含 GT | 新原文行包含 GT | 旧完整字段等于 GT | 新完整字段等于 GT |
|---|---:|---:|---:|---:|
| 职位 | 10/13 | 6/13 | 5/13 | 4/13 |
| 公司 | 10/14 | 9/14 | 3/14 | 9/14 |

公司完整值提取在这 5 份开发 PDF 上较旧版有所改善，但职位片段召回不足；不能用公司这个局部收益掩盖职位缺口。

**开发门禁预先固定**：新方案的完整字段精确命中不得低于旧方案的原文行包含率（两个类别都满足）；人工候选数不得超过旧完整清单的 1.5 倍。结果职位 -6、公司 -1，故失败；候选量虽减少，但不足以接受模型。

脚本在开发门禁失败时返回 new_test_read=false、new_holdout=null。本轮没有触碰 41–60 的冻结 GT，不能声称有新的独立测试集模型效果。

## 红→绿接口回归

- tests/test_span_proposer.py：训练池与保留集隔离、GT 仅用于训练、源字符偏移、相同 PDF 输出确定、未知文档联系信息不形成候选、未确认候选不改变文件。
- tests/test_span_proposer_experiment.py：预测先于加载 GT、冻结 split、精确命中与旧整行覆盖的固定门禁、门禁失败不能读取新测试集。

运行：

    uv run --python 3.12 python -m pytest tests/test_span_proposer.py tests/test_span_proposer_experiment.py -q
    uv run --python 3.12 python -m scripts.experiment_span_proposer --split development

不应以这份未通过实验为理由反复访问新的冻结测试集。

## 工程判断与下一步

正向 GT 字符区间接口已能保存一行内公司与职位的不同片段，但仅靠少量正向词汇结尾和局部边界无法对职位片段可靠泛化。继续在 5 份开发文件上加后缀、调词频，属于过拟合，不能当作推进 R7。

下一阶段优先明确模型任务：原生 PDF 文字块 → 字段边界 → 实体关系，分两层处理，补足经过独立复核的边界监督样本和“明确其他字段类别”对照，而不是把未标注背景默认为假字段。只有对新的未见样本的精确片段和完整工作记录有可靠增益，才能考虑接入第二步人工校对；用户原始 PDF 与五维评分仍保持隔离。

当前仍不存在经真实 HR 标注的评分效度，甲方演示的工程 PASS 与外部结构化解析 60.51% 继续分开陈述。
